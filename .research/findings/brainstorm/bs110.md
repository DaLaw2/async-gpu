## Final Epic Recommendations

### Tier 1 — Immediate (create now, start executing)

**1. `classical-ml` — Classical ML on GPU**
- User explicitly requested tree models
- Scope: decision tree inference + random forest + k-means (skip KNN — it's just GEMM)
- Async angle: weak, but user-requested = must do
- Complexity: Medium

**2. `gpu-dynamic` — Dynamic Control Flow on GPU**
- THE architectural advantage over CUDA graphs / TensorRT / TVM
- Demos: variable-length beam search, early-exit inference, data-dependent batching
- Async angle: EXTREME — this is what only async-gpu can do
- Complexity: Medium
- This is the skeptic's strongest new proposal

### Tier 2 — Near-term (create now, execute after Tier 1)

**3. `graph-algorithms` — Graph Algorithms with Async Scheduling**
- BFS, PageRank on CSR graphs
- Async angle: HIGH — frontier scheduling with warp yield on empty frontier
- Complexity: Medium

**4. `int4-gpt2` — INT4 GPT-2 Inference (reopen)**
- Low-hanging fruit, closes tracked gap
- Int4Linear + quantized weights already exist
- Complexity: Small

**5. `monte-carlo` — Monte Carlo with Async Convergence**
- Black-Scholes option pricing, Pi estimation
- Async angle: convergence detection — warps that converge early yield
- GPU PRNG with hostcall entropy seeding
- Complexity: Small-Medium

### Tier 3 — Long-term (defer, revisit later)

**6. `image-processing`** — Good demo value per effort, connects to YOLO
**7. `fft-signal`** — Demoted. Single-block FFT only if done. No async value.
**8. `sparse-ops`** — SpMV + CG solver only. Skip SpGEMM.
**9. `gpu-streaming`** — Interactive GPU server (needs more design work)
**10. `cublas-interop`** — Hostcall dispatches cuBLAS. Revolutionary but needs investigation.

### Explicitly Skipped:
- `tiled-dp4a` — Performance polish, not strategic
- `gpu-crypto` — No user, no differentiation
- `gpu-sort-db` — Too much effort, zero differentiation (maybe prefix scan only)

## Epics to Create Now

Create Tier 1 + Tier 2 epics (5 total). Tier 3 deferred to future brainstorm.

## Key Insight

"Building 3 demos that ONLY async-gpu can run is a recipe for impact. Building 10 inferior
reimplementations of NVIDIA's libraries is a recipe for irrelevance." — Skeptic

The strongest direction is: classical-ml (user requested) + dynamic control flow (unique
differentiator) + graph algorithms (async-native). These three prove breadth, leverage
the framework's unique features, and cover entirely new GPU compute domains.
