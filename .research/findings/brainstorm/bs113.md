**Trigger**: User feedback: "We only write demos, not a library users can actually call."
**Level**: Standard
**Epic**: library-api (T1, highest priority)

## 1. Current Crate Layout Assessment

### Workspace Structure

```
Cargo.toml (workspace)
├── members: gpu-host, gpu-protocol, warp-macro
├── resolver = "2"
└── exclude: patched-rustc, rustc-src
```

### Core Crates (in workspace)

| Crate | Type | Purpose | Public? |
|-------|------|---------|---------|
| `gpu-host` | lib+bin | Host-side SDK: launch kernels, hostcall, memory | Yes (user-facing) |
| `gpu-protocol` | lib | Shared constants/types between host and GPU | Internal |
| `warp-macro` | proc-macro | `#[warp_async]` state machine generation | Internal |

### GPU-Side Crates (NOT in workspace — nvptx64 target)

| Crate | Type | Purpose | Public? |
|-------|------|---------|---------|
| `gpu-runtime` | rlib | Facade for kernel authors: index, math, warp, thread, hostcall | Yes (user-facing) |
| `gpu-atomics` | rlib | System-scope PTX atomics | Internal |
| `gpu-libc` | rlib | Minimal libc shim for GPU | Internal |
| `gpu-kernel` | cdylib | Built-in kernel implementations (test/demo) | Internal (demo) |
| `gpu-kernel-std` | cdylib | Kernels using patched std (println!, Vec, File) | Internal (demo) |

### Key Observations

1. **No facade crate exists.** Users must `use gpu_host` for host and `use gpu_runtime` for kernel. There is no single `async-gpu` crate.

2. **gpu-host is a mixed bag — library + test harness + demo binary in one.** The crate contains:
   - **Library code** (7 core modules, ~5,700 lines): `gpu.rs`, `runtime.rs`, `hostcall.rs`, `memory.rs`, `mapped_mem.rs`, `error.rs`, `streams.rs`, `async_rt.rs`
   - **Test harness** (`main.rs` + 13 `tests_*.rs` files, ~23,500 lines): A 1,203-line `main.rs` that dispatches to 13 test modules via `ONLY_TEST=` env var filtering. This is the project's primary test runner, but it lives INSIDE the library crate as a binary target.
   - **Demo/model code** (~7,000 lines): `model.rs`, `model_generic.rs`, `model_yolo.rs`, `tokenizer.rs`, `yolo_backbone.rs`, `bench_harness.rs`
   - **NN framework** (~8,100 lines): `nn/` (layers, ops, tensor, autograd, models) + `onnx_rt/` (executor, fusion, proto)
   - **Embedded PTX** (7 PTX files): `ptx::KERNEL`, `ptx::EMBASSY_TEST`, etc.

3. **The binary target IS the test harness.** `[[bin]] name = "gpu-host"` with `required-features = ["gpt2"]` is not a user-facing binary — it's a monolithic test runner. `cargo run -- ONLY_TEST=generation` runs a specific test. This should be a separate test harness crate.

4. **Test modules have direct access to library internals.** The 13 `tests_*.rs` files are `mod` declarations in `main.rs`, so they can access `pub(crate)` items. Moving them out will require making some APIs `pub` or creating a test-support API.

5. **Feature flags gate demo code, but defaults pull everything in.** `default = ["gpt2"]` means a plain `cargo add gpu-host` brings safetensors, tiktoken-rs. Users don't need GPT-2 model loading to use the GPU launch API.

6. **warp-macro is only used by internal test kernels.** The `#[warp_async]` proc macro is used in exactly 2 files:
   - `crates/kernel/gpu-kernel/src/warp.rs` (the internal demo kernel)
   - `crates/core/gpu-host/src/tests_warp.rs` (test harness)
   The MIR pass now handles async on GPU automatically — `warp-macro` is a legacy DSL for the pre-MIR approach.

7. **Examples use diverse patterns.** Hostcall examples have separate `host/` and `kernel/` subdirectories. Std examples depend on `gpu-host` directly. No consistent structure.

8. **`cargo doc` produces a wall of noise.** Demo modules, test modules, protocol constants, internal memory helpers — all visible in rustdoc. A user looking for "how do I launch a kernel?" would drown in irrelevant types.

## 2. The Three-Layer Separation Problem

The user correctly identified the core issue: **library, demos, and tests are entangled.** Here is the proposed clean separation:

### Layer 1: Library Crates (what users `use`)

| Crate | Role | User imports |
|-------|------|-------------|
| `async-gpu` (NEW) | Host-side facade | `use async_gpu::gpu;` |
| `gpu-host` (cleaned) | Host implementation | Internal to facade |
| `gpu-runtime` (cleaned) | Kernel-side facade | `use gpu_runtime::prelude::*;` |
| `gpu-protocol` | Wire protocol types | Internal |
| `gpu-atomics` | PTX atomics | Internal to gpu-runtime |
| `gpu-libc` | libc shim | Internal to gpu-runtime |

### Layer 2: Examples/Demos (showcase code)

| Directory | Role |
|-----------|------|
| `examples/hostcall/*` | Hostcall API demos (host + kernel pairs) |
| `examples/std/*` | Patched-std demos (use gpu-host directly for NN etc.) |

### Layer 3: Test/Bench Infrastructure

| Crate/File | Role |
|------------|------|
| `crates/test/gpu-test-harness/` (NEW) | Extract current main.rs + tests_*.rs + bench_harness.rs |
| `crates/kernel/gpu-kernel/` | Test kernel implementations (linked by test harness PTX) |
| `crates/kernel/gpu-kernel-std/` | Test kernels using patched std |
| `crates/test/{async-hostcall,embassy,multi-warp,...}` | Existing test kernel crates |

## 3. Proposed Library Structure

### 3.1. Facade Crate: `async-gpu`

Create a new crate `crates/async-gpu/` that serves as the single entry point for host-side users:

```toml
[package]
name = "async-gpu"
version = "0.1.0"
description = "Rust async/await on GPU — clean, documented host-side API"

[features]
default = []
async = ["gpu-host/async"]  # tokio integration

[dependencies]
gpu-host = { path = "../core/gpu-host", default-features = false }
```

The facade re-exports a curated public API:

```rust
// crates/async-gpu/src/lib.rs

//! async-gpu — Rust async/await on GPU.
//!
//! # Quick Start (Host Side)
//!
//! ```rust
//! use async_gpu::gpu;
//!
//! fn main() -> async_gpu::Result<()> {
//!     let result: Vec<u32> = gpu::launch("my_kernel", 1024, 256)?;
//!     Ok(())
//! }
//! ```

// --- Core launch API ---
pub mod gpu {
    pub use gpu_host::gpu::{
        run, run_with_output, launch,
        custom, CustomLaunchBuilder, GpuContext, GpuResult,
    };
}

// --- Runtime for advanced use ---
pub use gpu_host::GpuRuntime;
pub use gpu_host::HostcallSession;
pub use gpu_host::MappedBuffer;
pub use gpu_host::Pipeline;

// --- Error types ---
pub use gpu_host::error::{GpuHostError, Result};

// --- Async integration (feature-gated) ---
#[cfg(feature = "async")]
pub mod async_rt {
    pub use gpu_host::async_rt::{AsyncGpuRuntime, GpuTask, HostcallEvent};
}
```

### 3.3. Clean Up gpu-host

After extraction, gpu-host becomes a pure library:

**Remove:**
- `[[bin]]` section from Cargo.toml
- `main.rs` → moved to test harness
- `tests_*.rs` (13 files) → moved to test harness
- `bench_harness.rs` → moved to test harness

**Change default features:**
- `default = []` (was `["gpt2"]`)

**Mark internal:**
- `pub(crate) mod mapped_mem` — raw CUDA alloc helpers (exposed via `MappedBuffer`)
- `pub(crate) mod ptx` — demo PTX, only needed by test harness
- `pub(crate) mod model`, `model_generic`, `model_yolo`, `tokenizer`, `yolo_backbone` — demo-specific
- `pub(crate) fn model_dir()` — demo helper

**Keep public:**
- `pub mod gpu` — the core launch API
- `pub mod runtime` — GpuRuntime
- `pub mod hostcall` — HostcallSession, HostcallBuffer, Pipeline
- `pub mod memory` — MappedBuffer
- `pub mod error` — GpuHostError, Result
- `pub mod streams` — GpuStream
- `pub mod async_rt` — tokio integration (feature-gated)
- `pub mod nn` — NN framework (feature-gated, legitimate library functionality)
- `pub mod onnx_rt` — ONNX runtime (feature-gated)

### 3.4. Clean gpu-runtime Prelude

The prelude currently exports ~60 items including 40+ protocol constants (`SERVICE_*`, `PKT_OFF_*`, `FILE_*`). These are implementation details.

**Keep in prelude** (user-facing):
- `gpu_hostcall_print`, `gpu_panic_init`, `gpu_result_init` — essentials
- `Mutex`, `MutexGuard` — sync primitives
- `GpuExecutor`, `GpuHashMap` — high-level types
- `block_on` — async executor
- Warp-level types: `WarpFuture`, `WarpExecutor`, `WarpPoll`, `WarpContext`
- Atomic helpers: `sys_load_acquire_u32`, `sys_store_release_u32`
- Common atomics: `activemask`, `lane_id`, `shfl_sync_idx_u32`, `syncwarp`

**Move to `gpu_runtime::protocol` (accessible but not in prelude)**:
- `SERVICE_*` (20+ constants)
- `PKT_OFF_*`, `CONTROL_*`, `NULL_INDEX`, `PACKET_SIZE`
- `FILE_*`, `TCP_*`, `TRACE_LEVEL_*`
- `CMD_*` constants

**Move to `gpu_runtime::hostcall` (accessible but not in prelude)**:
- `gpu_hostcall_request`, `gpu_hostcall_release`, `gpu_hostcall_trace`, `gpu_hostcall_assert`
- `sideband_alloc`, `sideband_reset`, `gpu_bulk_read`, `gpu_bulk_write`

### 3.5. warp-macro Assessment

`warp-macro` provides the `#[warp_async]` proc macro for generating WarpFuture state machines from sequential code. It is used in exactly 2 places:
1. `crates/kernel/gpu-kernel/src/warp.rs` — internal test kernels
2. `crates/core/gpu-host/src/tests_warp.rs` — test harness

The MIR pass now handles async on GPU transparently (as noted in the native-rust-dx epic success criteria). `warp-macro` is a **legacy DSL** from before the MIR pass existed.

**Recommendation**: Keep `warp-macro` in the workspace for now (it's used by tests), but:
- Remove from the facade crate's re-exports
- Do NOT document as a user-facing API
- Add a note in its crate doc: "Internal macro for pre-MIR-pass warp futures. Users should use standard async fn instead."
- Future task: migrate the 2 test files off warp-macro, then remove it

## 4. Toolchain Setup Plan

### Current State

Three scripts, no single entry point:
1. `build-toolchain.sh` — clone rustc, apply compiler patches, build stage-1
2. `apply-std-patches.sh` — patch std for nvptx64
3. `build-kernel-std.sh` — build kernel-std PTX + cubin

Plus a nightly toolchain (`nightly-2026-06-03`) with `rust-src` component.

### Proposed: Single Setup Script

Create `scripts/setup.sh` that orchestrates everything:

```bash
#!/bin/bash
# async-gpu setup — one command to get a working development environment.
#
# Usage:
#   ./scripts/setup.sh              # Full setup (first time)
#   ./scripts/setup.sh --quick      # Skip toolchain build, just patch std
#   ./scripts/setup.sh --check      # Verify setup is working
#
# What it does:
#   1. Verify prerequisites (CUDA, rustup, nightly toolchain)
#   2. Apply std patches to the nightly sysroot
#   3. Build the default kernel PTX files
#   4. Run a smoke test (compile + launch a trivial kernel)
```

**Two modes:**

1. **Quick setup (default):** Use the nightly toolchain from `rust-toolchain.toml` + apply std patches to its sysroot. This is what most users need. No rustc build.

2. **Full setup (--build-toolchain):** For contributors who need the patched compiler (MIR pass changes). Calls `build-toolchain.sh`.

### Verify Script

`scripts/setup.sh --check` should:
1. Verify `rustup show` has the right nightly
2. Verify patched std files exist in sysroot
3. Compile and run a trivial GPU kernel
4. Report pass/fail

## 5. Getting-Started Flow Design

### Step-by-Step (Under 30 Minutes)

#### Step 1: Clone and Setup (5 min)

```bash
git clone https://github.com/user/async-gpu.git
cd async-gpu
./scripts/setup.sh
```

Output: "Setup complete. Run `cargo test --test smoke` to verify."

#### Step 2: Write a Host Program (5 min)

```toml
# Cargo.toml
[dependencies]
async-gpu = { path = "../async-gpu/crates/async-gpu" }
```

```rust
// src/main.rs
use async_gpu::gpu;

fn main() -> async_gpu::Result<()> {
    let result: Vec<f32> = gpu::custom("vector_add")
        .ptx(include_str!("../kernel.ptx"))
        .threads(256)
        .elements(1024)
        .prepare()?;
    // ...
    Ok(())
}
```

#### Step 3: Write a Kernel (5 min)

```rust
// kernel/src/lib.rs
#![no_std]
#![feature(abi_gpu_kernel)]
use gpu_runtime::prelude::*;
gpu_runtime::panic_handler!();

#[no_mangle]
pub unsafe extern "gpu-kernel" fn vector_add(
    a: *const f32, b: *const f32, c: *mut f32, len: u32,
) {
    let idx = gpu_runtime::index::global_thread_idx() as u32;
    if idx < len {
        *c.add(idx as usize) = *a.add(idx as usize) + *b.add(idx as usize);
    }
}
```

#### Step 4: Build and Run (5 min)

```bash
cd kernel && cargo +nightly build --release --target nvptx64-nvidia-cuda
cp target/nvptx64-nvidia-cuda/release/kernel.ptx ../kernel.ptx
cd .. && cargo run --release
```

#### Step 5: Explore Examples (10 min)

```bash
cd async-gpu/examples/hostcall/hello-gpu && bash run.sh
```

## 7. What Internal Types Should Become `pub(crate)`

### In `gpu-host`

| Current | Proposed | Reason |
|---------|----------|--------|
| `pub mod mapped_mem` | `pub(crate)` | Raw CUDA alloc; users use `MappedBuffer` |
| `pub mod model` | `pub(crate)` (feature-gated) | Demo-specific |
| `pub mod tokenizer` | `pub(crate)` (feature-gated) | Demo-specific |
| `pub mod model_generic` | `pub(crate)` | Demo-specific |
| `pub mod model_yolo` | `pub(crate)` | Demo-specific |
| `pub mod yolo_backbone` | `pub(crate)` | Demo-specific |
| `pub mod ptx` | `pub(crate)` | Demo PTX, not user-facing |
| `pub fn model_dir()` | `pub(crate)` | Demo helper |

**Complication**: The test harness (currently in `main.rs`) uses `mod tests_basic;` etc., which gives it access to `pub(crate)` items. Once extracted to a separate crate, it can only access `pub` items. Two approaches:

1. **Keep some items `pub` but not in facade**: The test harness depends on `gpu-host` and can see all `pub` items, but `async-gpu` facade only re-exports the clean subset. Users who depend on `async-gpu` never see the noise.

2. **Create a `test-support` feature**: `gpu-host` exposes `#[cfg(feature = "test-support")] pub mod ptx` for the test harness, hidden from normal library users.

**Recommended: Option 1** (simpler). The facade is the user's API surface. `gpu-host`'s `pub` items that aren't re-exported by `async-gpu` are implementation details visible only to power users who bypass the facade.

### In `gpu-runtime`

Move 40+ protocol constants from prelude to submodules (see Section 3.4).

## SUMMARY

79% of gpu-host/src/ (23,735 lines) is test harness code living inside the library crate, making `cargo doc` useless and the crate structure incomprehensible to users. The fix is five themes: (1) **lib-extract**: extract the monolithic test harness into its own crate — this is the single highest-impact change; (2) **lib-facade**: create an `async-gpu` facade crate with curated re-exports; (3) **lib-cleanup**: hide internal types, clean the gpu-runtime prelude, deprecate the legacy warp-macro DSL; (4) **lib-toolchain**: single `scripts/setup.sh` for environment setup; (5) **lib-docs**: getting-started guide + rustdoc that passes the 30-minute litmus test.
