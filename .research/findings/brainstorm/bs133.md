# Brainstorm 133 — ownership-memory: Rust lifetimes map to GPU memory tiers

**Trigger**: ownership-memory story activated by 3/3 majority vote. Previous om-design/om-compiler/om-demo archived at cycle 639.
**Cycle**: 642 | **Level**: Standard

---

## Key Insight

BlockScope and GridScope already allocate from different address spaces (shared=addrspace(3), global=addrspace(1)) and return lifetime-bounded refs. But both return `&'scope mut [T]` — the type system can't distinguish them. Wrapping these in phantom-typed `SharedRef<'block, T>` / `GlobalRef<'grid, T>` lets the borrow checker enforce memory hierarchy rules at zero runtime cost, and hints LLVM toward address-space-specific codegen.

## Approach: Library-First, Compiler-Optional

Start with pure library-level types (no rustc changes). The `for<'scope>` HRTB pattern on `block_scope()`/`grid_scope()` already prevents scope-allocated refs from escaping. Adding a phantom `AddrSpace` tag makes the tier visible to the type checker. Compiler MIR pass work (register promotion) is a follow-on investigation, not a prerequisite.

## Features

1. **om-tiered-types** — SharedRef/GlobalRef wrapper types (3 tasks: investigate, design, implement)

## LLVM Address Space Mapping

| Tier     | CUDA     | PTX qualifier | LLVM addrspace | Scope lifetime |
|----------|----------|---------------|----------------|----------------|
| Register | register | (implicit)    | 0 (default)    | owned `T`      |
| Shared   | __shared__ | .shared     | 3              | `'block`       |
| Global   | __device__ | .global     | 1              | `'grid`        |

## Risk: addrspace in PTX codegen

LLVM's nvptx backend infers address space from pointer provenance. `cvta.shared` converts a shared-memory offset to a generic pointer — subsequent loads use generic space, not `.shared`. The tiered types may not produce `.shared` loads without explicit `asm!`. Investigation task om-tiered-types.1 will determine if this is a real issue or if LLVM's optimizer recovers the address space.
