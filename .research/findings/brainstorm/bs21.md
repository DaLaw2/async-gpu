# bs21 — Synthesis: GPU-Native Async Pipeline

**Trigger**: Major epic definition — GPU-native async pipeline vision
**Level**: deep (proposer + skeptic)

## Consensus

1. **WarpFuture architecture is correct** — both agree. Per-thread Futures cause 1/32 SIMT waste, WarpFuture is the right answer for I/O.
2. **Hybrid executor (ADR-10) is the right model** — WarpFuture for I/O, per-thread blocks for compute. Both agree.
3. **The demo/example approach is right** — prove the vision through working examples, not abstract infrastructure.
4. **All infrastructure is in place** — 13 hostcall services work, sideband buffer works, WarpFuture works. No new protocol/crate/compiler changes needed.

## Disagreements Resolved

### Proc macro expansion (Proposer: expand; Skeptic: don't)
**Resolution: DON'T expand the proc macro.** The skeptic is right — expanding `#[warp_async]` to support all hostcall services, let bindings, and per_thread blocks is writing a mini-compiler. The hand-written WarpFuture state machine IS the API. The demo should be hand-written, not proc-macro-generated. The proc macro stays as-is for the trivial case.

### Is a multi-step demo needed? (Proposer: yes; Skeptic: hybrid-executor.1 is enough)
**Resolution: YES, a real data pipeline demo is needed.** hybrid-executor.1 is print→compute→print. That proves WarpFuture↔per-thread switching works, but it doesn't demonstrate:
- Real data flowing through the pipeline (file → GPU → file)
- Multiple different I/O operations (open, read, write, close)
- GPU autonomy (self-coordinating 7 I/O steps without CPU intervention)

The user explicitly asked for "multi-step pipeline demo" that's runnable. print→compute→print is not that.

### How many tasks? (Proposer: 7; Skeptic: 1)
**Resolution: 3 tasks.** The minimum to deliver:
1. Warp-level hostcall wrappers (building blocks for any hand-written WarpFuture)
2. File transform demo (hand-written WarpFuture, NOT proc macro)
3. README overhaul (per user request: "讓人一眼就能看出來專案的價值")

Conditional paths, loops, persistent kernels, proc macro expansion — all deferred.
