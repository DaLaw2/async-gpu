# BS38 Synthesis: Public API Epic + GPU Inference Re-evaluation

## Trigger
User-directed deep brainstorm. User criticized:
1. No public API — project has zero external usability after 140 cycles
2. Decision gates too lenient — transformer-layer.7 "PASSED" by relaxing tolerance 10x
3. gpu-inference epic declared "complete" despite only validating concept feasibility

## Proposer-Skeptic Consensus

Both agents agree on:

1. **transformer-layer.7 was a false pass.** 60% of elements fail at the stated tolerance (atol=0.01, rtol=0.01). Relaxing to (0.05, 0.10) and declaring victory was wrong. The gpu-inference epic is NOT complete.

2. **f16 precision is the #1 risk.** Compound f16 quantization across 3+ GEMM stages produces ~10% relative error in ONE layer. Across 12 layers through nonlinearities, output may diverge catastrophically. This must be fixed BEFORE scaling.

3. **Attention kernel needs a complete rewrite for seq>32.** The 1024×1024 attention matrix (4MB f32) doesn't fit in shared memory (48-100KB). FlashAttention-style tiling is required — this is not a parameter change.

4. **7 of ~13 required components don't exist at all.** Embedding, causal mask, weight loading, tokenizer, multi-layer, LM head, KV cache are all missing.

5. **"GPU autonomous orchestration" is misleading for inference.** Inference is a fixed sequential DAG. The host is the control plane. Drop this framing.

## Key Disagreement: Public API Timing

**Proposer**: Start Public API (host-sdk) and inference in parallel. SDK benefits inference development.

**Skeptic**: Public API is premature. Build system is unpublishable (nightly + -Zbuild-std + manual PTX copy + SM86 only). Fix inference first.

**Resolution**: The skeptic is right that a *published* public API is premature. However, extracting a library crate from gpu-host (host-sdk) is valuable for internal development — it cleans up the inference codebase. The compromise:
- Create a "Public API" epic with themes for host-sdk, kernel-lib, build-tooling, examples-docs
- But **defer** kernel-lib, build-tooling, and examples-docs until inference works
- Start host-sdk immediately (it benefits inference internally)

## Decisions

### 1. gpu-inference Epic: Reset Success Criteria

Old (too lenient):
- MHA with "real weight values" → used synthetic weights
- Match PyTorch "within f16 tolerance (atol=1e-2, rtol=1e-2)" → relaxed to (0.05, 0.10)
- GPU "autonomously orchestrates" → host-orchestrated

New (concrete, non-negotiable):
1. Real GPT-2 small weights loaded from HuggingFace safetensors
2. BPE tokenizer produces correct token IDs matching HuggingFace
3. Single-layer output matches PyTorch reference within (atol=0.01, rtol=0.01) — no relaxation
4. 12-layer stacked output produces correct top-1 next-token prediction
5. Given "The capital of France is", greedy decoding produces text containing "Paris"
6. Greedy-decoded output matches HuggingFace GPT-2 token-for-token for 3+ test prompts

### 2. transformer-layer Theme: Revert to "partial"

The existing kernels (LayerNorm, GELU, attention, FFN, GEMM) are valid building blocks. But the theme's success criteria ("Single-layer forward pass matches PyTorch GPT-2 layer 0 output within f16 tolerance") was NOT met. Mark as incomplete — new tasks needed under revised themes.

### 3. New Themes for gpu-inference Epic

**Theme: precision-fix** (Phase 1, CRITICAL)
- Fix f16 compound error; keep f32 between layers
- Decision gate: single layer matches PyTorch at (0.01, 0.01)

**Theme: model-loading** (Phase 1)
- Load real GPT-2 weights from safetensors
- Validate single layer with real weights against PyTorch reference

**Theme: tokenizer** (Phase 1, independent)
- BPE tokenizer on host side
- Can use `tokenizers` crate or implement manually

**Theme: attention-scale** (Phase 2)
- Causal mask support
- Scale attention to seq>32 (FlashAttention-style or multi-block)
- Decision gate at seq=128

**Theme: full-inference** (Phase 3, depends on all above)
- Embedding, 12-layer stack, LM head, sampling, autoregressive loop
- End-to-end text generation

### 4. Public API Epic: New

**Theme: host-sdk** (start now — benefits inference)
- Extract library crate from gpu-host
- GpuDevice, KernelBuilder, HostcallRuntime abstractions

**Theme: kernel-lib** (defer until inference works)
**Theme: build-tooling** (defer until inference works)
**Theme: examples-docs** (defer until inference works)

### 5. Execution Order

```
Phase 1 (parallel):
  precision-fix ──┐
  model-loading ──┤── Decision Gate: single layer + real weights matches PyTorch at rtol=0.01
  tokenizer ──────┤
  host-sdk ───────┘

Phase 2 (after Phase 1 gate passes):
  attention-scale ── Decision Gate: causal attention works at seq=128

Phase 3 (after Phase 2):
  full-inference ── Decision Gate: greedy "The capital of France is" → "Paris"

Phase 4 (after Phase 3):
  kernel-lib, build-tooling, examples-docs
```

### 6. Decision Gates (strict, no relaxation)

| Gate | Condition | If FAIL |
|------|-----------|---------|
| precision-fix.3 | Single layer matches PyTorch at (0.01, 0.01) with f32 intermediates | Try f32-only GEMM (no Tensor Cores) |
| model-loading.4 | Real-weight single layer matches PyTorch at (0.01, 0.01) | Investigate weight layout bugs |
| attention-scale.3 | Causal attention at seq=128 matches PyTorch | Limit to seq≤128 with naive multi-block |
| full-inference.5 | Greedy decoding matches HuggingFace token-for-token | Debug per-layer, identify divergence point |

### 7. PyTorch Reference Strategy

The skeptic correctly noted we never ran PyTorch. We need reference values. Strategy:
- Pre-compute PyTorch reference outputs on a machine with PyTorch installed
- Check in reference tensors as binary files (or generate via a Python script the user runs once)
- Compare GPU output against these checked-in references
- This avoids needing PyTorch in the build environment

## Risk Summary

| Risk | Severity | Action |
|------|----------|--------|
| f16 precision death spiral across 12 layers | Critical | Fix first — f32 inter-layer storage |
| Attention scaling to seq>32 | High | FlashAttention research, significant effort |
| Build system not packageable | High | Defer public release, focus on internal |
| Random weights hiding real bugs | High | Load real weights immediately |
| Decision gates too lenient | High | Fixed rtol/atol, PyTorch reference, no relaxation |
| LM head 50,257 dimension | Medium | Pad to 50,272 or edge-tile handling |
| 156 kernel launches overhead | Medium | Measure, optimize later if needed |
