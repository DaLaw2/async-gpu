## Technical Analysis

### Gap 1: CI Coverage Holes — 4 Kernel Builds Not in CI

`ci-lint.sh` builds 9 PTX kernels but **misses** these example kernels:
- `examples/async-pipeline/kernel` — not in `PTX_KERNELS` list
- `examples/parallel-search/kernel` — not in `PTX_KERNELS` list
- `examples/warp-cooperative/` — scratch workspace, not a real example

The host-side checks also miss `async-pipeline`:
- `async-pipeline/host` — not in `cargo check` list (line 68-71)

**Impact**: A breaking change to gpu-runtime or gpu-protocol could silently break these example kernels.

### Gap 2: warp-cooperative Directory Is Not a Real Example

`examples/warp-cooperative/` contains:
- A `test-warp-crate` Cargo.toml (workspace scratch)
- `rustc-ice-*.txt` (ICE crash log from MIR pass development)
- `mir_dump/` directory
- No `host/` subdirectory, no `run.bat`/`run.sh`

It is a development scratch workspace, not a user-facing example. The README's crate map does not mention it. It should either be promoted to a proper example or removed/moved to a dev/ directory.

### Gap 3: Missing Run Scripts for 2 Examples

Run scripts (`run.sh`/`run.bat`) allow one-command demo execution:
| Example | run.sh | run.bat |
|---------|--------|---------|
| hello-gpu | YES | YES |
| async-io | YES | YES |
| async-pipeline | NO | YES |
| parallel-search | NO | NO |
| vector-math | YES | YES |

`parallel-search` and `async-pipeline` (Linux) are missing run scripts.

### Gap 4: No Per-Example README Files

None of the 5 examples has a README.md. The main README has 1-2 sentence descriptions, but:
- No explanation of what the kernel does step-by-step
- No expected output shown
- No "what to look for in the PTX" guidance
- A contributor exploring examples has no local documentation

### Gap 5: Test Coverage Is Minimal (3 Integration Tests Only)

`crates/core/gpu-host/tests/gpu_integration.rs` has only 3 `#[test]` functions:
1. `test_write_thread_idx` — basic kernel launch
2. `test_hostcall_print_hello` — hostcall print
3. `test_buffered_print` — bulk print

Missing test coverage:
- File I/O hostcall (open/read/write/close)
- Sideband bulk read/write
- Error propagation (GPU returns error → host receives it)
- Multi-warp concurrent hostcall
- HostcallSession persistence across launches

The 94 kernels in gpu-kernel are not exercised by `cargo test` — they require manual GPU execution.

### Gap 6: 822 `unsafe` Blocks in gpu-host with No Safety Comments

`unsafe` count across gpu-host/src: 822 occurrences across 14 files. While GPU/CUDA interop inherently requires unsafe, many blocks likely lack `// SAFETY:` comments explaining the invariants relied upon. This is a documentation debt that makes code review and contribution harder.

### Gap 7: Build Script Uncommitted Changes

`git status` shows:
- `scripts/build-toolchain.ps1` — modified (unstaged)
- `scripts/postprocess-ptx.sh` — deleted
- `scripts/build-toolchain.bat` — new file (untracked)

The `.ps1` → `.bat` migration appears incomplete. `build-toolchain.bat` supersedes `.ps1` but the old `.ps1` has modifications and the new `.bat` is not committed.

### Gap 8: No CONTRIBUTING.md or Developer Guide

ARCHITECTURE.md exists for understanding the system, but there is no guide for:
- How to add a new example
- How to add a new kernel
- How to run the test suite
- How to modify the MIR pass
- Code style conventions beyond what's in CLAUDE.md

## Skeptic Challenges

**"Is more CI coverage worth the maintenance?"** — Yes. async-pipeline is the flagship demo and a regression there would be embarrassing. Adding 2 lines to ci-lint.sh is trivial.

**"Do examples need individual READMEs?"** — For a research project with 5 examples, inline README descriptions suffice. But for contributor/adopter experience, per-example READMEs with expected output are valuable. Prioritize the 2 most complex (async-pipeline, parallel-search).

**"Should we add more integration tests?"** — The 3 existing tests prove the test harness works. Adding file I/O and error propagation tests would catch real regressions. But GPU tests require hardware, so they can't run in standard CI. Priority: medium.

**"Is cleaning up warp-cooperative worth a task?"** — Yes, it is confusing to have a broken directory in examples/. Either promote it with proper structure or move to dev/.
