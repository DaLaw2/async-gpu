## Consensus

Both proposer and skeptic agree:
1. The project needs to transition from "it compiles" to "it is useful"
2. Multi-warp concurrent async is the central thesis proof
3. Documentation polish is at diminishing returns
4. Upstreaming, ecosystem integration, and multi-GPU are premature

## Key Dispute: What the Agent Can Productively Do

The skeptic correctly identifies that multi-warp and benchmarks require GPU hardware to test. The agent should focus on:
1. **Network I/O** — fully implementable and CI-verifiable (host-side service handlers + GPU-side Futures)
2. **Multi-warp design** — architecture document, code written but tagged UNTESTED
3. **Focused safety audit** — critical hostcall protocol code paths only (not all 822 unsafe blocks)

## Decisions

### New Epic: network-io (medium priority)
Add TCP/HTTP hostcall services so GPU kernels can make network requests. This extends the hostcall protocol to network I/O following the exact same pattern as file I/O.

Success criteria:
1. SERVICE_TCP_CONNECT / SERVICE_TCP_SEND / SERVICE_TCP_RECV defined in gpu-protocol
2. Host-side service handlers implemented (std::net)
3. GPU-side Future types (GpuTcpConnectFuture, GpuTcpSendFuture, GpuTcpRecvFuture)
4. Demo kernel that connects to a server, sends data, receives response

### New theme: net-protocol (epic: network-io)
Define network hostcall service IDs and packet layout.
- net-protocol.1: Investigation — design TCP service protocol (service IDs, fd model, sideband usage)
- net-protocol.2: Experiment — implement service IDs and packet constants in gpu-protocol

### New theme: net-host (epic: network-io)
Implement host-side TCP service handlers.
- net-host.1: Experiment — implement TCP connect/send/recv handlers in gpu-host listener

### New theme: net-gpu (epic: network-io)
Implement GPU-side TCP Future types.
- net-gpu.1: Experiment — implement GpuTcpConnectFuture/SendFuture/RecvFuture in gpu-runtime

## Key Insight
Network I/O is the highest-value work the agent can do without GPU hardware. It extends the proven hostcall pattern, compiles on stable (host side), and is verifiable via CI. Multi-warp and benchmarks are important but require GPU testing — tag as UNTESTED if implemented.
