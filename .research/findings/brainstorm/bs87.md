# Brainstorm 87 — Synthesis: Post-Plateau Direction
**Cycle**: 303 | **Date**: 2026-03-15 | **Level**: Deep

## Consensus

Both proposer and skeptic agree on one thing: **formal verification (TLA+) is the highest-value work**. The CAS protocol is the system's foundation, hardware testing is unavailable, and TLA+ is perfectly suited to verifying lock-free protocol designs without running code.

## Key Disagreements Resolved

### Plugin system: SKIP (skeptic wins)
The proposer pitched a HostcallService trait + registry. The skeptic's counterargument is decisive: with zero users, a plugin system is premature abstraction. The match statement *is* the extension point. When the project has external users who need stable extension APIs, this becomes relevant. Not before.

### Multi-GPU: PARK (skeptic wins)
Can't design multi-GPU coordination when single-GPU behavior is unvalidated. Architecture fiction.

### Build system: FIX (skeptic adds value)
The proposer ignored that build scripts are in flux (git status shows modified .ps1, deleted .sh, new .bat). Stabilizing existing scripts > architecting xtask replacement.

### Tutorials/comparison: SKIP (skeptic wins)
Can't tutorial or benchmark software that can't be run.

## Decisions

### New Epic: formal-verification (medium priority)
TLA+ model of the CAS hostcall protocol. Scope tightly to packet lifecycle FSM.

### New Theme: tla-model (formal-verification)
- tla-model.1 (investigation): Learn TLA+ basics, identify which protocol aspects to model
- tla-model.2 (experiment): Write TLA+ spec for packet lifecycle (FREE→FILLING→READY→PROCESSING→DONE→FREE)
- tla-model.3 (experiment): Add multi-agent contention (2 warps + 1 host), verify safety + liveness

### New Theme: build-stabilize (codebase-health)
- build-stabilize.1 (experiment): Finalize build-toolchain scripts (.ps1/.bat/.sh state)

### New Theme: validation-prep (codebase-health)
- validation-prep.1 (experiment): Write first-run validation checklist (hardware/driver/toolchain requirements + smoke test instructions)

### Existing Theme: profiling-timestamps (skip for now)
Timestamp fields in hostcall packet — one task, not a theme. Defer until TLA+ work is done.

## Execution Plan
1. build-stabilize.1 (quick fix, unblocks clean git status)
2. validation-prep.1 (documentation, independent)
3. tla-model.1 → tla-model.2 → tla-model.3 (sequential, main work)

## Key Insight
The project needs depth, not breadth. One TLA+ model that verifies (or finds bugs in) the CAS protocol is worth more than three new untested features. After TLA+, the highest-value next step is enabling someone with GPU hardware to validate the system.
