## Analysis

### Option 1: GPU Async Channels (RECOMMENDED — highest priority)
GPU executor exists but tasks can't communicate. Channels (oneshot + mpsc) enable:
- Task-to-task data passing without host round-trip
- Pipeline patterns: producer → channel → consumer
- Waker integration: receiver task yields until sender writes

**Why highest priority**: Directly extends the working executor. Channels are the missing piece for real async patterns on GPU. Every async runtime needs channels.

**Implementation approach**:
- Oneshot<T>: single producer, single consumer, backed by mapped memory slot with atomic state
- Mpsc<T>: lock-free ring buffer in mapped memory, CAS-based enqueue, atomic waker
- Integration with GpuExecutor's waker mechanism

### Option 2: Shared Memory Primitives
Fast intra-block communication via `.shared` memory (on-chip SRAM, ~100x faster than global).
- SharedArray<T, N> with warp-safe access
- Reduction primitives (sum, min, max across block)
- Useful for compute-heavy kernels but less aligned with async story

### Option 3: Integration Testing Harness
Automated end-to-end GPU test framework:
- Test runner that compiles kernel + launches + verifies results
- Property-based testing for concurrent protocols
- Regression suite for all existing features
