## Analysis

### What's missing for production use?
1. **Multi-GPU** — GpuRuntime hardcoded to device 0, no multi-context
2. **CUDA Streams** — single stream, no overlap of compute + I/O
3. **GPU Memory Pools** — bump allocator only, no deallocation/fragmentation mgmt
4. **Pre-built toolchain** — 2-3 hour build on first setup, biggest onboarding friction

### What would have highest ecosystem impact?
1. **Multi-GPU support** — enables scaling, needed for any serious deployment
2. **CUDA stream support** — enables pipelining, 40-60% latency reduction
3. **Pre-built rustc binaries** — 90% reduction in new-user setup friction
4. **AMDGPU PoC** — validates platform abstraction, broadens reach

### What's lowest-hanging fruit?
1. Unpark `warp-batch-io` — design exists (ADR-10), 3-4 tasks
2. Pre-built toolchain — CI artifact upload + download script, 2 tasks
3. Multi-GPU — mostly API changes in GpuRuntime, 3 tasks

## Recommendations

### New Epic: `production-ready`
**Title**: Production Readiness — multi-GPU, streams, memory management
**Priority**: high
**Criteria**:
1. GpuRuntime supports multiple GPUs (device selection + multi-context)
2. CUDA stream support for overlapping compute and I/O
3. GPU memory pool with deallocation (slab or buddy allocator)
4. Pre-built toolchain binaries via CI (reduce setup to < 10 min)

### Parked Work: unpark warp-batch-io
- Known design, quick win for hostcall efficiency under load
- Can run as a side task within codebase-health

### Deferred: AMDGPU
- Investigation only (target spec, kernel porting feasibility)
- Deferred until production-ready foundations solid
